Architecture Système

Weighted Fusion Engine — 4 Pipelines Asynchrones

Ghost Sentry repose sur un moteur de fusion pondérée orchestrant quatre pipelines d'analyse indépendants lancés en parallèle via asyncio.gather(). Chaque pipeline produit un score partiel entre 0 et 1. Le score final est calculé par somme pondérée avant d'être soumis à l'API Groq pour synthèse et explicabilité.

Principe fondamental
Tout ce qui peut être analysé en parallèle l'est. Les 4 pipelines s'exécutent simultanément. Le moteur d'agrégation ne s'active qu'une fois tous les scores collectés. Cela réduit la latence totale à celle du pipeline le plus lent, non à leur somme.
🔗
URL Pipeline
WHOIS · DNS · SSL · Typosquatting · Homoglyphe
Poids : 30%
Analyse structurelle complète de chaque URL extraite. Vérification WHOIS (âge domaine), records DNS/MX/SPF, validité SSL. Détection de typosquatting et d'homoglyphes Unicode via la base Consortium Unicode + distance de Levenshtein.
🧠
BERT Pipeline
distilbert-base-uncased · Fine-tuned phishing
Poids : 30%
Classification Deep Learning via distilbert-base-uncased fine-tuné sur corpus phishing. Analyse contextuelle du texte : détection de manipulation psychologique, d'urgence artificielle, et de patterns linguistiques caractéristiques.
🗄️
RAG Pipeline
ChromaDB · all-MiniLM-L6-v2 · URLHaus 11k+
Poids : 20%
Recherche de similarité vectorielle (384 dimensions) sur une base de 11 000+ URLs malveillantes indexées depuis URLHaus. Chaque requête retourne les Top-3 voisins les plus proches avec distance cosinus normalisée.
📝
Text Pipeline
Analyse sémantique · Patterns · Mots-clés
Poids : 20%
Analyse sémantique du corps de l'email : détection de patterns d'urgence, cohérence expéditeur/domaine, analyse headers (From vs Reply-To), présence de demandes d'identifiants ou de données bancaires.

Formule de Fusion Pondérée

Python — Weighted Fusion
def weighted_fusion(scores: dict) -> float:
    """Score final par somme pondérée des 4 pipelines."""
    weights = {
        'url':  0.30,   # URL analysis (WHOIS, DNS, homoglyphe)
        'bert': 0.30,   # DistilBERT deep learning classifier
        'rag':  0.20,   # RAG similarity (ChromaDB + URLHaus)
        'text': 0.20,   # Text semantic analysis
    }
    score = sum(scores.get(k, 0.0) * w for k, w in weights.items())
    return round(min(score, 1.0), 4)

Détail Technique

Les 8 Étapes de l'Architecture

Étapes 1 & 2 — Capture et Dispatch

Étape 1 (Capture) : Ghost Sentry intercepte les emails avant livraison via deux modes. En production, le Milter Hook Postfix suspend la transaction SMTP sur le port 25 et transmet le payload à FastAPI. En mode démonstration, le mode test autonome permet d'analyser des emails synthétiques sans accès à une boîte mail réelle — idéal pour les présentations.

Étape 2 (Dispatch) : L'orchestrateur LangChain reçoit l'EmailPayload validé par Pydantic, puis lance les 4 pipelines simultanément via asyncio.gather(). Le timeout de 500ms par pipeline garantit que le système reste réactif même si un analyseur rencontre une latence réseau.

Python — EmailPayload + Dispatch
from pydantic import BaseModel, EmailStr
from typing import List, Optional
import asyncio, time

class EmailPayload(BaseModel):
    message_id:  str
    sender:      EmailStr
    subject:     str
    body_text:   Optional[str] = None
    body_html:   Optional[str] = None
    headers:     dict
    attachments: List[Attachment] = []
    received_at: float = time.time()

async def dispatch_parallel(payload: EmailPayload) -> dict:
    """Lance les 4 pipelines en parallèle via asyncio.gather()"""
    results = await asyncio.gather(
        pipeline_url.arun(payload),
        pipeline_bert.arun(payload),
        pipeline_rag.arun(payload),
        pipeline_text.arun(payload),
        return_exceptions=True
    )
    keys = ['url', 'bert', 'rag', 'text']
    return {k: (r.score if not isinstance(r, Exception) else 0.0)
            for k, r in zip(keys, results)}

Étape 3a — URL Pipeline (Poids : 30%)

Le pipeline URL combine quatre vérifications complémentaires. Aucune ne suffit seule — un attaquant peut contourner chaque filtre pris isolément. C'est leur combinaison qui donne un score fiable.

WHOIS
Âge du domaine
Un domaine de phishing est typiquement enregistré 2–7 jours avant l'attaque, puis abandonné. Moins de 7 jours → +0.60. Moins de 30 jours → +0.40.
DNS
Records MX / SPF
Absence de record MX = pas de vrai serveur mail derrière le domaine. Absence de SPF = pas de configuration email légitime. Chaque absence ajoute au score.
HOMO
Détection Homoglyphes Unicode
La base Unicode Consortium identifie les caractères "confusables" (ex : 'а' cyrillique U+0430 vs 'a' latin). Combiné à la distance de Levenshtein (seuil adaptatif 2/3), détecte paypal-secure.com, pаypal.com, etc.
RAG2
Similarité vectorielle URL
L'URL est transformée en vecteur et comparée à la collection url_threats (ChromaDB). Distance cosinus normalisée → score de similarité avec les URLs malveillantes connues.

Étape 3b — BERT Pipeline (Poids : 30%)

distilbert-base-uncased est un modèle Transformer allégé (40% plus rapide que BERT-base) fine-tuné sur un corpus labellisé de phishing et d'emails légitimes. Il capture les manipulations psychologiques que les règles statiques ne peuvent pas détecter : urgence artificielle, ton autoritaire, incohérences contextuelles.

Python — BERT Classifier
from transformers import pipeline

# Chargement du modèle fine-tuné (une seule fois au démarrage)
bert_classifier = pipeline(
    "text-classification",
    model="distilbert-base-uncased-finetuned-phishing",
    device=-1  # CPU suffisant pour l'inférence
)

def bert_score(email_body: str) -> float:
    """Retourne probabilité phishing ∈ [0,1]."""
    text = email_body[:512]  # Token limit DistilBERT
    result = bert_classifier(text)[0]
    # Label PHISHING → score direct, LEGITIMATE → 1 - score
    if result['label'] == 'PHISHING':
        return result['score']
    return 1.0 - result['score']

Étape 4 — RAG Pipeline / ChromaDB (Poids : 20%)

La base vectorielle ChromaDB contient 11 000+ URLs malveillantes issues d'URLHaus (feeds malware actifs), indexées sous forme de vecteurs de 384 dimensions via all-MiniLM-L6-v2. Elle est initialisée une seule fois via python tools/links_db.py et enrichie automatiquement après chaque confirmation admin.

Python — ChromaDB RAG Query
import chromadb
from sentence_transformers import SentenceTransformer

# Initialisation (une seule fois au démarrage)
client  = chromadb.PersistentClient(path="/data/chromadb")
encoder = SentenceTransformer("all-MiniLM-L6-v2")  # 90 MB, local
url_col = client.get_or_create_collection(
    name="url_threats",
    metadata={"hnsw:space": "cosine"}
)

def rag_score_url(url: str) -> float:
    """Similarité cosinus vs base URLHaus 11k+ URLs."""
    vec     = encoder.encode(url).tolist()
    results = url_col.query(query_embeddings=[vec], n_results=3)
    if not results['distances'][0]:
        return 0.0
    # Distance cosinus : 0=identique, 2=orthogonal
    return round(1.0 - min(results['distances'][0]) / 2.0, 4)

Étape 5 — Groq API : Llama 3.3 70B (Explicabilité)

Après la fusion pondérée, le score numérique seul ne suffit pas pour un système de sécurité. L'API Groq avec Llama 3.3 70B génère une explication en langage naturel du verdict — essentielle pour les décisions HITL et l'audit. La latence de 180–300ms via les LPU Groq rend cette étape compatible avec les exigences temps réel.

Python — Groq Explainability
from groq import Groq
import os, json
from dotenv import load_dotenv

load_dotenv()
groq_client = Groq(api_key=os.getenv("GROQ_API_KEY"))

SYSTEM_PROMPT = """Tu es un expert en cybersécurité.
Analyse le résumé d'analyse anti-phishing et retourne UNIQUEMENT un JSON :
{"score": float, "verdict": "CLEAN|SUSPICIOUS|MALICIOUS",
 "reason": string (max 200 chars), "confidence": "high|medium|low"}"""

def groq_explain(score: float, pipeline_scores: dict,
               email_summary: str) -> dict:
    user_msg = f"""
Scores pipeline : {pipeline_scores}
Score fusion : {score}
Résumé email : {email_summary[:500]}
"""
    resp = groq_client.chat.completions.create(
        model="llama-3.3-70b-versatile",
        messages=[{"role": "system", "content": SYSTEM_PROMPT},
                  {"role": "user",   "content": user_msg}],
        temperature=0.05,
        max_tokens=256,
        response_format={"type": "json_object"}
    )
    return json.loads(resp.choices[0].message.content)

Fonctionnalités Innovantes

📷
Anti-Quishing — QR Code Phishing
Ghost Sentry décode systématiquement chaque image attachée via pyzbar + Pillow. Si une image contient un QR code, l'URL encodée est extraite et injectée dans le pipeline URL pour analyse complète. ⚡
Groq LPU — Inférence Ultra-Rapide
Les LPU (Language Processing Unit) de Groq sont des puces spécialisées pour l'inférence séquentielle. Llama 3.3 70B s'exécute à ~800 tokens/s contre ~80 tokens/s sur GPU RTX A2000. La latence de l'étape d'explicabilité passe de 3–8s (local) à 180–300ms (Groq).

🗄️
Base URLHaus — 11 000+ URLs
La base vectorielle ChromaDB est pré-alimentée depuis URLHaus (feeds malware actifs). python tools/links_db.py télécharge, vectorise et indexe automatiquement les URLs malveillantes. La base s'auto-enrichit après chaque confirmation admin via le mécanisme HITL + Reinforcement Learning.

Mode Test Autonome — Sans IMAP
Ghost Sentry peut fonctionner sans accès à une boîte mail réelle. Le mode --verify analyse un corpus d'emails synthétiques intégré au projet, permettant des démonstrations complètes devant un jury ou des tests CI/CD sans dépendance à une infrastructure mail externe.
